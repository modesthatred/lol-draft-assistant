# LoL Draft Assistant

Локальный помощник для драфта League of Legends. По хоткею читает состав
из клиента и показывает твоих мейнов, отсортированных по оценке винрейта:
иконка, примерный винрейт под ней, цвет полоски, почему именно этот пик.

Как только ты закрепляешь пик (или наводишь на чемпиона), сверху появляется
блок **первых 2-3 предметов** по текущему патчу и обувь — что покупать.

Работает офлайн во время драфта: статистика заранее скачивается с OP.GG и
лежит в SQLite, расчёт занимает ~2 мс.

---

## Быстрый старт

1. Запусти `dist\DraftAssistant.exe`.
2. Сразу откроется **окно настроек** — выбери роль и 5-6 своих мейнов.
3. Нажми «Сохранить». Приложение само скачает статистику с OP.GG
   (≈30 секунд, показывает прогресс).
4. В драфте жми **F8** — оверлей покажет лучший пик из твоего пула.

Пулы в конфиге по умолчанию **пустой**: чужие мейны за тебя не выдумать.

## Управление оверлеем

| Действие | Как |
|---|---|
| Обновить | **F8** или **Пробел** (фокус на окне) |
| Настройки | **⚙** в правом верхнем углу или **ПКМ** по окну |
| Скрыть | **Esc** |
| Показать снова | **F8** |
| Выйти | **×** в углу, **ПКМ → Выход** или **Q** |

Окно без системного заголовка, поэтому в таскбаре его не видно — закрывай
через **×** или ПКМ-меню. Позиция запоминается, окно можно перетаскивать.

## Настройка

Окно настроек (⚙) сохраняет конфиг рядом с программой, в папку `data\`:

```
<папка программы>\data\config.json
```

Приложение полностью переносимое: и данные, и лог, и кэш лежат внутри
папки сборки. В `%LOCALAPPDATA%` ничего не пишется — можно всю папку
скопировать на флешку или в другой компьютер.

```jsonc
{
  "pool": ["Yone", "Ahri", "Zed", "Sylas", "Akali", "Fiora"], // 5-6 мейнов
  "role": "mid",                       // top | jungle | mid | adc | support
  "auto_role": true,                   // роль берётся из драфта, ручной выбор
                                      // как запасной вариант
  "pools": {                           // свои мейны на каждую роль
    "jungle": ["Shen", "Vi", "Nautilus"],
    "mid": ["Ahri", "Sylas"]
  },
  "hotkey": "F8",
  "window": { "opacity": 0.94, "x": null, "y": null },  // x/y запомнятся
  "weights": {
    "counter":    0.55,   // вклад матчапа против врагов
    "synergy":    0.30,   // вклад синергии с союзниками
    "comp":       0.15,   // вклад оценки состава команды
    "worst_case": 0.35    // внутри counter: доля худшего матчапа
  },
  "show": { "icons": true, "comp_notes": true, "always_on_top": true },
  "items": {
    "enabled": true,     // показывать блок первых предметов
    "show_boots": true,  // добавлять обувь в конец списка
    "show_count": 3      // сколько предметов: 2 или 3
  },
  "sync": { "max_age_hours": 24, "patch_check_hours": 6 }
}
```

Изменения применяются сразу — пул пересобирается на лету. Имя в `pool`
можно писать так, как оно в игре: `"Lee Sin"`, `"Dr. Mundo"` или
`"Master Yi"`.

Если клиент запущен из нестандартного места, укажи путь к папке с игрой в
файле `<папка программы>\data\lol_path.txt` одной строкой,
например `D:\Games\League of Legends`.

## Как считается оценка

Оценка — взвешенная сумма, а не «в среднем по всем»:

- **counter (0.55)** — средний винрейт против выбранных врагов, но с
  поправкой на худший матчап (`worst_case`): чем опаснее один плохой
  противник, тем сильнее просадка.
- **synergy (0.30)** — винрейт с уже выбранными союзниками.
- **comp (0.15)** — насколько чемпион вообще нужен этому составу.

Дополнительно:

- чемпион, которого **уже забанили враги**, помечается `[забанен]` и
  подсвечивается красным;
- в подписи видно риск бана и худший матчап;
- если данных мало (например, мейн с чужой роли — Lee Sin против мидовых
  врагов), рядом пишется `данных 43%`, и оценке стоит доверять меньше.

Винрейт под иконкой — **оценка в текущем драфте**, не общий винрейт
чемпиона по всем играм.

## Первые предметы

Блок появляется **сразу после пика**, а не в конце драфта: пока ты выбираешь
чемпиона, список собирать рано.

- Если пик уже закреплён — берётся твой чемпион (`localPlayerCellId`).
- Если пика ещё нет — берётся чемпион, на которого наведён курсор.
- Метка `пик` / `наведение` показывает, откуда взят билд.

Источник — `op.gg/lol/champions/{champ}/items/{role}`. OP.GG отдаёт не список
покупок, а связки «предмет + предмет» с числом игр, поэтому порядок
собирается жадно: первым идёт предмет из самых популярных связок, второй —
из связок, где первый уже есть, и так далее. Обувь идёт отдельной секцией
и в конец списка не попадает.

Каждому предмету проставлен патч, под который он скачан. Поскольку после
патча OP.GG меняет билды заметно, но по времени свежие данные ещё
проверяются как актуальные, номер патча сверяется отдельно: раз в
`patch_check_hours` приложение спрашивает у Data Dragon текущий патч и, если
тот изменился, перекачивает статистику даже не по расписанию.

Если билд собрали для другой роли, чем указана в настройках (пикнул
top-чемпиона при пуле на mid), приложение возьмёт любую роль, для которой
данные есть, — молчаливую пустоту в оверлее появляться не должно.

Блок отключается в настройках: ⚙ → **Предметы**.

## Роли и фолбэк

OP.GG не отдаёт страницу контрпиков для чужой роли. Если твой мейн —
Lee Sin, а ты играешь на миде, код сначала пробует твою роль, потом
остальные по очереди и берёт ту, где есть данные. Фактическая роль
записывается в базу, поэтому в следующий раз она уже известна.

Синергии всегда тянутся для роли из `config.role`.

## Источники данных

| Что | Откуда |
|---|---|
| id, иконки, теги | Data Dragon (`ddragon.leagueoflegends.com`) |
| текущий патч | Data Dragon (`/api/versions.json`) |
| контрпики | `op.gg/lol/champions/{champ}/counters/{role}` |
| синергии | `op.gg/lol/champions/{champ}/synergies/{role}` |
| билд и обувь | `op.gg/lol/champions/{champ}/items/{role}` |
| состав драфта | локальный LCU `https://127.0.0.1:<port>/lol-champ-select/v1/session` |

Важно:

- страница `.../builds` у OP.GG одинакова для всех чемпионов — как
  источник не используется;
- запросы к OP.GG идут последовательно с паузой, кэш обновляется раз в
  24 часа — это бережёт и сайт, и твой трафик;
- парсер привязан к текущей вёрстке OP.GG. Если сайт поменяет разметку,
  синк перестанет находить строки — чинить нужно `draft/opgg.py`. Для
  билдов есть запасной путь: если счётчик игр в связках пропал, порядок
  строится по винрейту, а не обрывается пустым списком.

## Где работает, а где нет

Приложение читает состав только из **настоящего драфта** — рангед, обычная
игра, ARAM-драфт. Там клиент держит эндпоинт
`/lol-champ-select/v1/session`.

**Не работает** на экране подбора ботов в тренировочном режиме
(«Инструмент для тренировки»): это экран лобби, а не пик-бан, клиент
отдаёт на `/lol-champ-select/v1/*` код 404. Состав оттуда недоступен
принципиально — там нет эндпоинта с составом. Вместо тишины приложение
покажет, в какой фазе клиент, например:

> Сейчас не драфт (сейчас лобби, а не драфт). Поддерживаются рангед,
> обычная и ARAM…

Так что для проверки бери обычную игру или ARAM, а не тренировочный режим.

## Поиск клиента

Путь к игре не зашит: приложение перебирает диски и ищет
`Riot Games\League of Legends\Lockfile`. Порядок поиска:

1. ручной путь из настроек или `<папка программы>\data\lol_path.txt`;
2. запомненный результат в `league_path.txt`;
3. **путь у запущенного клиента** — читается через `psapi`, без запуска
   внешних процессов (≈10 мс), поэтому клиент можно не искать перебором;
4. перебор дисков — только если первые три не сработали и не чаще раза в
   минуту, иначе каждое нажатие F8 при выключенном клиенте ждало бы
   полсекунды.

Чтобы задать путь один раз и забыть: ⚙ → **Папка с игрой** → «Обзор…»
(или «Найти сам»). Путь сохраняется в `lol_path.txt` и переживает
перезапуск. Проверяется наличие `Lockfile`, `LeagueClient.exe` или имени
папки «League of Legends», поэтому задать путь можно и до запуска игры.

Если автопоиск не справился, тот же файл можно заполнить вручную одной
строкой.

Второй экземпляр не запускается: показывается сообщение, хоткей остаётся
у первой копии.

## Команды (для отладки, из исходников)

```powershell
python -m draft              # обычный запуск с GUI
python -m draft --once       # разовый расчёт в консоль
python -m draft --sync       # обновить статистику и выйти
python -m draft --force      # обновить при старте, даже если кэш свежий
python tests\test_app.py     # регресс-тесты (без сети)
```

Лог всегда пишется в `<папка программы>\data\app.log` — в `.exe
консоли нет, поэтому смотреть надо туда.

## Трей и второй экземпляр

Оверлей сделан без системного заголовка, поэтому в таскбаре его не видно.
Чтобы приложение можно было найти и закрыть:

- **Значок в трее.** ПКМ по нему → «Показать оверлей» или «Выход».
- **Повторный запуск** не создаёт вторую копию, а поднимает уже открытое
  окно. Если окно потерялось — ищите значок в трее.

## Структура

```
draft/
  champions.py  Data Dragon: id, теги, иконки, resolve имени
opgg.py       парсеры контрпиков, синергий и билдов OP.GG, подбор слагов
  cache.py      SQLite: матчапы, синергии, метрики, билды, сроки обновления
  lcu.py        Lockfile, Basic auth, разбор /lol-champ-select/v1/session
  scoring.py    оценка мейнов под конкретный состав
  ui.py         tkinter-оверлей: пики, блок предметов, иконки
  settings_ui.py  окно настроек: роль, пул, хоткей, прозрачность, путь к игре,
                 блок предметов
  hotkey.py     глобальный Win32-хоткей RegisterHotKey
  main.py       связка LCU -> скоринг -> оверлей, автосинк, логи
tests/
  test_app.py   регресс-тесты: LCU, конфиг, кэш, оверлей, настройки,
                поиск клиента, выход из приложения, парсер и кэш предметов,
                разрыв Tk-ссылок при закрытии
run.py          entrypoint для PyInstaller
```

## Известные ограничения

- Первый запуск тянет статистику по сети (≈30 секунд). Если OP.GG недоступен,
  приложение покажет ошибку и продолжит работать на старых данных.
- Если в системе `F8` занят другой программой, хоткей не зарегистрируется —
  приложение об этом напишет в лог, останется `Пробел` и ПКМ-меню.
- Смена хоткея применяется сразу: слушатель пересоздаётся на лету,
  перезапускать приложение не нужно.
- Экран подбора ботов в тренировочном режиме — это лобби, а не драфт:
  `/lol-champ-select/v1/session` там отдаёт 404, и состава через LCU не
  получить. Работает там, где есть настоящий пик-бан.

## Что не проверено на реальном клиенте

Разбор LCU покрыт тестами на фикстурах, но живой ответ клиента не
проверялся: сборка идёт без запущенного League. Билды предметов проверены
живым запросом к OP.GG (Ahri, Fiora, Kassadin, Jinx — патч 16.19.1), а вот
определение своего пика по `localPlayerCellId` и появление блока в оверлее
в настоящем драфте ещё не виделись. При первом реальном драфте стоит глянуть
`app.log` — если парсер не пережил формат сессии, правки в `draft/lcu.py`.

Блок предметов помечен как «наведение», пока пик не закреплён, — это
ожидаемо: список собирается по одному чемпиону, а не по всему драфту.
